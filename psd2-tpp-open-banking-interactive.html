Perspective: Licensed TPP (PISP + AISP)
This diagram shows what you build and operate as a licensed Third-Party Provider integrating with bank APIs under PSD2. Solid-border boxes = your systems (Cloud Run, Pub/Sub, Cloud SQL, etc.). Dashed-border boxes = external parties you interact with (bank APIs, eIDAS registries, PSU browser) — you do not control these.

💳 Payment Initiation (PISP)

MERCHANT REQUEST → TPP GATEWAY → BANK ADAPTER → POST /v1/payments → SCA REDIRECT → PSU AUTH → STATUS POLLING → MERCHANT CALLBACK

📊 Account Information (AISP)

CONSENT CREATE → SCA AUTH → VALID (90 DAYS) → GET /v1/accounts → GET /v1/accounts/{id}/transactions → TOKEN REFRESH → DELIVER

✕ Failure Modes & Recovery

SCA REDIRECT LOST · CERT EXPIRY · TOKEN REFRESH FAIL · STUCK PAYMENT · RACE CONDITION · AUDIT TRAIL
